# BOM 项目发现与决策

## Requirements

- 依据 [需求描述.txt](../requirements/需求描述.txt) 制定项目方案。
- 先形成计划，再与用户逐项敲定，最后交付确认后的实施计划。
- 使用 `planning-with-files` 与 `grill-me` 技能。
- 禁用且不使用 `superpower` 技能。
- 当前阶段不实施业务代码。
- 建设轻量级 Web 系统，Python 后端、SQLite 数据库。
- 管理四层 BOM：原材料 → 半成品 → 单元 → 整机；“需要组装”的原材料还可递归包含其他原材料。
- 原材料支持单条录入、Excel 批量导入、编码规则维护/Excel 覆盖导入、智能推荐编码和版本尾号递增。
- 编码必须唯一；名称与规格需做重复/相似检查，并为批量导入提供逐项确认的冲突处理界面。
- 外协或自制原材料自动标记为需要组装，并维护双向引用；所有组成关系必须阻止递归死循环。
- 半成品、单元、整机分别独立维护，支持搜索选择上一级组件、名称补全、树状构成与反向引用。
- 除整机外，同层实体支持多对多选配关系；编辑组成时可从选配项中替换。
- 四类实体支持复制并生成不重复的新编码，同时保留下级组成关系。
- 可预览和导出技术 BOM（保留层级）及生产 BOM（仅展开后的初级原材料），并支持多对象批量导出 Excel。
- 整机、单元、半成品支持 1–5 个同层模块的 BOM 差异对比。
- 物料记录“当前在用归属产品机型”，支持从物料精确反查所属产品。
- 组成、编码、选配及增删模块等变化需写入可审计历史日志。
- 整机、单元、半成品具有有效/试产/停用状态，列表可筛选，反向引用需显示状态。

## Research Findings

- 会话恢复检查未发现需要同步的旧会话上下文。
- 原始需求文件现归档在 [docs/requirements/需求描述.txt](../requirements/需求描述.txt)。
- 尚未发现既有 `task_plan.md`、`findings.md`、`progress.md` 或 `AGENTS.md`。
- `planning-with-files` 要求规划文件位于项目根目录，并在阶段完成后更新。
- `grill-me` 要求沿决策树逐项提问、每次只问一个问题、每题给出推荐答案；能通过仓库探索回答的问题不得询问用户。
- 仓库目前没有应用代码；除需求文本外还有宏工作簿、编码规则 Word、原材料导入模板、生产 BOM 示例、优化需求 Word 和架构需求 PDF，可用于校验字段、编码规则和输出格式。
- 现有宏工作簿包含 7 张表：目录、原材料清单、输入半成品、输入单元、输入整机、输出技术 BOM（有层级）、输出生产 BOM（仅原材料）。
- 原材料现有字段包括物料编码、物料识别码、名称、规格型号、属性、单位、备注、上一版本名称、发票名称、材料属性、变更记录；新模板另有“当前在用归属产品机型”。
- 组成关系至少需要“父项、子项、数量”；现有工作簿中的半成品/单元/整机以父行和其后子行表示组成。
- 技术 BOM 示例按“层级（按链接次数）”逐行输出；生产 BOM 示例为扁平原材料清单，保留并累计数量。
- 原材料编码模板提供 143 条左右的分类/规则行，规则结构包含大类、小类、材料属性、编码开头、编码示例、说明；常见规则如 `10.1XXX.0`，序号位范围 000–999。
- 优化需求明确提出：编码模糊前缀提示最大值；半成品 N 层嵌套；反向检索后批量替换/调量/增加/删除；日志 Excel 导出；账户、部门、角色权限；日志推送；状态变化后产品归属保留历史但灰显。
- 架构 PDF 将选配解释为“优选/备选”，使用场景包括多家供应商、多种物料、自制/外购原材料以及半成品组件。
- 优化需求给出的原材料导入判定为：名称+规格 ≥95% 完全重复、名称 50%–95% 近似、名称 <50% 全新；其半成品等模块表格又给出 ≥95% 重复、≥85% 近似，阈值口径并不统一。
- 当前目录不是 Git 仓库，方案文件无法通过 Git 状态跟踪。
- 宏工作簿当前约有：原材料 3,446 个、半成品 373 个、单元 664 个、整机 418 个；组成关系约 17,808 条（半成品 4,113、单元 10,356、整机 3,339）。
- 现有单元并非只包含半成品，也直接包含原材料；整机同时直接包含单元、半成品和原材料。因此“固定页面层级”不等于“关系只能连接相邻层”。
- 历史工作簿中约有 56 个编码同时出现在原材料和整机位置、1 条孤儿父项关系；初始化迁移必须先输出冲突清单并确认处置。
- 历史工作簿中有 27 组完全相同的“名称+规格”，涉及 55 行；迁移时保留原始事实并标注历史导入来源，不以日常相似提醒自动阻断。
- 历史工作簿中的原材料属性主要为外购 2,928、外协 474、自制 34，并有少量字段错位迹象；迁移需要字段级校验和异常报告。
- 生产 BOM 样表只有一个工作表，标题位于合并的 `A1:K1`，第 2 行是 11 列表头，共有 231 条明细。
- 生产 BOM 11 列依次为：序号、物料编码、名称、规格型号、单位、数量、备注（黄色：修改后名称）、上一版本名称、发票名称、材料属性、变更记录。
- 样表 231 个物料编码全部唯一，支持“生产 BOM 按完整编码汇总叶子料”的判断。
- 样表数量全部为数值，最小 0.013、最大 40，至少 16 行为非整数；数量必须使用定点小数计算和存储。
- 样表中规格型号 217/231、备注 46/231、上一版本名称 99/231、发票名称 180/231、变更记录 7/231，材料属性整列为空；除编码、名称、单位、数量外，其余业务字段应允许为空。
- 样表没有公式、筛选、冻结窗格或隐藏行列；明细也没有实际填充色，尽管备注列表头说明黄色用于标记修改后名称。

## Technical Decisions

| Decision | Rationale |
|----------|-----------|
| 先调查需求与仓库，再开始访谈 | 避免向用户询问可从现有材料直接查明的事实 |
| 将“事实 / 推断 / 待决策”分开记录 | 防止初版方案把假设误当成已确认需求 |
| 初版数据模型采用统一物料主表 + BOM 关系图 | 既支持四类独立界面，也兼容原材料自组装及已确认的受控跨级直挂；不支持半成品嵌套 |
| 所有 BOM 写操作在服务层和数据库约束层校验无环 | 单纯依赖前端无法可靠阻止递归死循环，批量导入和批量维护同样需要防护 |
| 半成品不允许包含半成品 | 用户明确否定半成品 N 层嵌套；补充文档中的 N 层要求被本次决定覆盖 |
| 仅原材料允许包含同类型原材料 | 用户明确原材料可由其他原材料组合而成；仍必须执行无环校验 |
| 允许受控跨层直挂 | 用户采用推荐：单元可直接含半成品/原材料，整机可直接含单元/半成品/原材料；与现有工作簿一致 |
| 首期采用简化账户权限 | 用户确认包含基础权限但强调权限管控不是重点；采用固定角色，不建设复杂 RBAC |
| 首期不做日志主动推送 | 用户采用推荐；保留日志查询、对象时间线、首页近期变更和 Excel 导出，主动推送后续扩展 |
| 首期包含批量 BOM 维护 | 用户采用推荐；支持反查后批量替换、调量、增加、删除，并要求预览、变更原因和批次审计 |
| 外购/外协/自制是原材料来源属性 | 用户采用推荐；不增加物料类型，界面提供分库筛选，外协/自制默认启用并强制维护组装来源 |
| 编码拆分为主体与版本尾号 | 用户采用推荐；完整编码全局唯一，同一主体可有多个版本，并建立显式版本关联 |
| 历史版本编码保持原样 | 用户采用推荐；`.0/.1` 不改写，内部解析数值，后续新增版本按两位尾号格式生成 |
| BOM 行采用轻量字段 | 用户采用推荐：子物料、定点数量、显示顺序、行备注；单位继承子物料，同父子重复时合并数量 |
| 高度相似物料允许确认后创建 | 用户采用修正建议；完整编码不重复时，名称+规格 ≥95% 经红色强提醒和二次确认后可创建；编码重复仍绝对拒绝 |
| 四类物料统一相似度分级 | 用户采用推荐：名称+规格 ≥95% 红色二次确认，名称 50%–95% 黄色候选，名称 <50% 不提示；阈值可配置 |
| 选配采用默认项加备选项的同类型替代组 | 用户采用推荐；每个 BOM 位置只选一个，预览/比较/导出只计算当前选中项，整机本身不建选配组 |
| 技术与生产 BOM 使用不同展开口径 | 用户采用推荐：技术 BOM 按路径展开不合并、数量取本层用量；生产 BOM 展开叶子、路径相乘并按完整编码汇总 |
| 批量 BOM 导出采用 ZIP | 用户采用推荐：每个对象独立生成 Excel，再统一打包 ZIP；文件名含完整编码、名称和 BOM 类型 |
| 首期不做审批流 | 用户采用推荐：维护人员确认后立即生效，必须填写变更原因并记录前后值、操作人和时间 |
| 首期采用局域网 Windows 单机部署 | 用户确认符合现场环境；SQLite 位于主机本地磁盘，客户端浏览器访问，不依赖互联网并每日备份 |
| 首批按单人操作设计 | 用户说明首批只有 1 人操作，不需要复杂并发设计；保留基础账户仅用于身份和审计 |
| 模块对比采用差异矩阵表 | 用户采用推荐：1–5 个同类型对象，叶子原材料为行，显示累计数量、颜色差异、来源路径并可导出 Excel |
| xlsm 是一次性初始化迁移输入 | 用户进一步澄清：工作簿用于形成首版数据库，但不是日常输入模板、项目产出或运行依赖，迁移过程不得执行 VBA |
| 初始化迁移采用预检确认流程 | 用户确认：先解析暂存并生成异常清单，人工确认后正式入库，再按实体、关系和代表性 BOM 对账；原文件不修改 |
| 首版编码规则按资料分类初始化 | 用户采用推荐：原材料取编码登记模板表2，半成品/单元/整机参考编码标准和历史编码；之后数据库规则为唯一生效来源 |
| 编码规则覆盖导入采用受控替换 | 用户采用推荐：校验并预览差异和兼容性后事务替换，保存旧规则快照，失败整批回滚 |
| 停用对象保留历史引用但禁止新增引用 | 用户采用推荐：停用项默认不参与选料，已有 BOM 不自动改变，预览/导出继续计算并显示警告 |
| 产品机型归属完全自动计算 | 用户采用推荐：有效/试产为当前归属，停用为灰色历史归属，不允许人工编辑且可下钻引用路径 |
| 删除采用引用保护和软删除 | 用户采用推荐：有引用禁止删除，无引用仅软删除并可恢复；完整编码永久保留，不允许重新分配 |
| 复制分为新版本和新物料 | 用户采用推荐：前者保持主体并递增版本，后者生成新主体且从 `.01` 开始；均复制组成但不复制历史日志 |
| 半成品/单元/整机新建默认试产 | 用户采用推荐：创建时可改有效，不能默认停用；原材料不使用三态状态 |
| 外协/自制改外购前必须清空组成 | 用户采用推荐：不自动删除关系，先展示影响并填写原因，清空组装来源后才允许修改属性 |
| 日常 Excel 导入按所选行原子提交 | 用户采用推荐：全部行先暂存，可分批勾选；本次所选行任一失败则整组回滚，其他行保留 |
| BOM 正式输出遵循人工显示顺序 | 用户采用推荐：技术 BOM 在父项内排序；生产 BOM 汇总后保留叶子料首次出现位置，临时列表排序不影响导出 |
| 日常 Excel 导入首期只支持原材料 | 用户采用推荐；半成品/单元/整机及 BOM 关系通过页面和复制维护，历史 xlsm 由一次性脚本初始化 |
| 技术栈采用 Vue 3 + FastAPI | 用户采用推荐；前后端同机部署，对用户呈现为单一网站 |
| 物料识别码是核心编码，旧物料编码是辅助索引 | 用户确认：`10.1001.0` 作为全局唯一和 BOM 引用键，`B01.A` 类字段可选且只用于搜索/兼容 |
| 审计日志对所有账户不可修改删除 | 用户采用推荐：包括管理员也只能查询/导出，错误以新的修正事件追加 |
| 新版本不自动升级现有 BOM | 用户采用推荐：既有 BOM 保持旧版本；升级通过反查批量替换并审计，旧版本保留追溯 |

## Implementation Defaults

- 无阻塞实施的业务未决项。
- 实现默认值：相似文本执行 Unicode NFKC、大小写/空白/常见标点与单位表达规范化，再用 RapidFuzz 计算可解释分数。
- 实现默认值：原材料导入错误报告为 Excel，保留原始行并附状态、错误原因、相似候选和处理结果。
- 实现默认值：技术/生产 BOM Excel 严格保持已确认的 12/11 列结构，并增加基本可读性样式（标题、表头、列宽、冻结表头和自动筛选）。
- 实现默认值：生产 BOM 完全展开至叶子原材料，仅计算选配组的当前选中项。

## Confirmed Decisions

1. 半成品不能包含半成品，不支持半成品 N 层嵌套。
2. 原材料可以包含多个原材料，从而组装为新的原材料；这是唯一允许的同类型嵌套。
3. 允许受控跨层直挂：半成品→原材料；单元→半成品/原材料；整机→单元/半成品/原材料。
4. 首期包含基础登录及简化权限，权限管控不是重点；不做复杂的部门/字段级授权。
5. 首期不做 BOM 日志主动推送，只提供日志查询、对象时间线、首页近期变更和 Excel 导出。
6. 首期包含批量 BOM 维护，安排在核心 BOM、反向追溯和审计能力之后。
7. 外购、外协、自制作为原材料来源属性；外协/自制默认需要组装，界面提供独立筛选入口。
8. 物料编码拆为主体与版本尾号；完整编码全局唯一，同一主体允许多个显式关联版本。
9. 历史单数字版本尾号保持原样；内部按数值比较，新版本使用两位尾号。
10. BOM 关系只保存子物料、定点数量、显示顺序和行备注；单位继承物料档案，同父子重复时合并数量。
11. 系统必须保留新物料创建入口：用户按编码规则逐级选择非 `X` 位置，系统推荐流水号和版本尾号后创建。
12. 名称+规格高度相似但完整编码不重复时允许创建；必须红色提醒、展示候选并二次确认。
13. 四类物料统一相似分级：≥95% 红色、50%–95% 黄色、<50% 无提示，阈值可配置。
14. 选配采用同类型替代组：一个默认项、多个备选项；每个 BOM 位置只选一个，输出只计算当前项。
15. 技术 BOM 按路径完整展开、重复节点不合并、数量取本层用量；生产 BOM 展开叶子、路径相乘并按完整编码汇总。
16. 批量导出采用“一对象一份 Excel”，统一打包为 ZIP 下载。
17. 首期不做审批流；维护人员确认后立即生效，所有受控变更必须填写原因并完整审计。
18. 首期部署在局域网单台 Windows 主机，SQLite 使用本地磁盘，其他电脑通过浏览器访问并执行每日备份。
19. 首批只有 1 名实际操作人员，不为高并发增加复杂基础设施。
20. 模块对比采用差异矩阵表，支持 1–5 个同类型对象、累计数量、颜色差异、路径下钻和 Excel 导出。
21. `BOM物料清单管理(1).xlsm` 作为一次性历史数据初始化输入，形成首版数据库；不作为日常输入模板、项目产出或运行依赖。
22. 初始化迁移执行“预检—人工确认—正式入库—数量/BOM 对账”，原始 xlsm 保持不变。
23. 首版编码规则按资料分类初始化，初始化后以数据库规则为唯一运行来源。
24. 编码规则覆盖导入必须预览差异、检查兼容性、事务替换并保留旧快照。
25. 停用的半成品/单元/整机不能新增引用，但已有引用保留，输出继续计算并明确警示。
26. “当前在用归属产品机型”由 BOM 自动反查，不允许人工维护；停用机型保留为历史归属。
27. 所有对象采用受引用保护的软删除；编码删除后仍永久占用，管理员可恢复无引用软删除对象。
28. 复制支持“新版本”和“新物料”两种模式；复制组成关系，审计仅记录来源对象。
29. 半成品、单元、整机新建默认“试产”，原材料不设置有效/试产/停用状态。
30. 外协/自制原材料改为外购前，必须人工确认影响并清空其组装来源，系统不自动删除关系。
31. 日常 Excel 导入先暂存，可分批勾选；每次所选行作为原子事务，失败则整组回滚。
32. BOM 正式预览/导出按人工显示顺序；生产 BOM 汇总后保留首次出现位置。
33. 首期日常 Excel 批量导入仅支持原材料档案，其他类型通过页面录入和复制维护。
34. 前端采用 Vue 3 + TypeScript，后端采用 Python FastAPI，同机部署。
35. “物料识别码”作为系统核心物料编码；旧“物料编码”仅作为可选辅助索引码。
36. 审计日志对所有账户只读且不可删除，错误通过追加新的修正操作处理。
37. 创建新版本不会自动改变现有 BOM；新建时推荐最新可用版本，已有 BOM 升级必须显式替换。
