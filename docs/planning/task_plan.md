# BOM 项目方案敲定计划

## Goal

依据 [需求描述.txt](../requirements/需求描述.txt) 与现有仓库事实，通过逐项访谈形成双方确认、可执行且可验收的项目方案与实施计划；本阶段不进入业务代码实现。

## Current Phase

Complete

## Phases

### Phase 1: 需求与仓库发现

- [x] 阅读并结构化 [需求描述.txt](../requirements/需求描述.txt)
- [x] 检查仓库结构、现有技术栈与约束
- [x] 区分已知事实、合理推断和待用户决策项
- [x] 将发现记录到 [findings.md](findings.md)
- **Status:** complete

### Phase 2: 初版项目方案

- [x] 明确初版目标、范围和非目标
- [x] 拟定架构、模块、数据、接口和交付策略
- [x] 拟定测试、验收、风险与里程碑
- [x] 将方案决策及理由写入 [项目方案.md](../design/项目方案.md)
- **Status:** complete

### Phase 3: Grill-me 逐项敲定

- [x] 按依赖顺序一次提出一个决策问题
- [x] 每个问题附推荐答案及理由
- [x] 根据答复更新方案，并继续下一分支
- [x] 直到所有会影响实施的分支达成共识
- **Status:** complete

### Phase 4: 最终计划交付

- [x] 汇总已确认决策与实现默认值
- [x] 形成分阶段、可执行、可验收的 [实施计划.md](../design/实施计划.md)
- [x] 检查需求覆盖、依赖关系和未决项
- [x] 准备向用户提交最终方案与文件位置
- **Status:** complete

## Key Questions

1. [需求描述.txt](../requirements/需求描述.txt) 所定义的业务目标、角色、核心流程与验收标准是什么？
2. 现有仓库对技术栈、部署、兼容性和集成方式有哪些约束？
3. 哪些关键选择无法从仓库查明，必须由用户决策？
4. 怎样拆分里程碑才能最早验证高风险假设？

## Decisions Made

| Decision | Rationale |
|----------|-----------|
| 本轮只做方案敲定和计划，不实现业务代码 | 用户明确要求先制定项目方案并共同敲定 |
| 使用 `planning-with-files` 和 `grill-me` | 用户明确指定；前者沉淀过程，后者逐分支消除歧义 |
| 禁用 `superpower` | 用户明确要求，本轮不调用或依赖该技能 |
| 初版推荐 FastAPI + Vue 3 + SQLAlchemy/Alembic + SQLite WAL | 满足复杂前端交互，同时保持单机部署和可追踪数据库结构升级能力 |
| Vue 3 + FastAPI 技术组合正式确认 | 用户在 Grill-me 第 31 问采用推荐；同机部署为单一网站 |
| 物料识别码为核心编码，旧物料编码为辅助索引 | 用户在 Grill-me 第 32 问确认；唯一性、版本、规则和 BOM 引用统一使用识别码 |
| 审计日志对所有账户只读 | 用户在 Grill-me 第 33 问采用推荐；包括管理员也不能修改删除，错误以新事件修正 |
| 新版本不自动升级既有 BOM | 用户在 Grill-me 第 34 问采用推荐；升级必须显式替换、预览影响并审计 |
| 统一物料主表与 BOM 图作为系统内核 | 支持原材料自组装及已确认的受控跨级直挂，同时集中实施环路校验 |
| 禁止半成品嵌套；仅原材料可嵌套原材料 | 用户在 Grill-me 第 1 问中明确决定；原材料递归仍执行环路校验 |
| 允许受控跨层直挂 | 用户在 Grill-me 第 2 问中采用推荐；以父子类型白名单限制合法组合 |
| 首期包含简化账户权限 | 用户在 Grill-me 第 3 问确认；仅固定角色和账户启停，不建设复杂权限系统 |
| 首期不做主动通知推送 | 用户在 Grill-me 第 4 问采用推荐；保留完整日志和近期变更视图 |
| 首期包含批量 BOM 维护 | 用户在 Grill-me 第 5 问采用推荐；批量操作必须预览、填写原因并记录批次审计 |
| 外购/外协/自制作为原材料来源属性 | 用户在 Grill-me 第 6 问采用推荐；提供分库视图，外协/自制强制维护组装来源 |
| 编码拆为主体与版本尾号 | 用户在 Grill-me 第 7 问采用推荐；完整编码全局唯一，同一主体可关联多个版本 |
| 历史版本编码不改写 | 用户在 Grill-me 第 8 问采用推荐；内部解析数值，新版本按两位尾号生成 |
| BOM 行采用轻量字段 | 用户在 Grill-me 第 9 问确认；生产 BOM 样表证明数量需要定点小数，输出信息由关系、物料主数据和审计组合生成 |
| 保留编码引导的新物料创建入口 | 用户纠正第 10 问的前提；名称/规格重复检查不得取消编码规则下拉引导功能，阻止边界待继续确认 |
| 高度相似不绝对阻止创建 | 用户在修正后的 Grill-me 第 10 问采用推荐；完整编码唯一是硬约束，相似检查是强提醒加二次确认 |
| 四类物料统一相似度分级 | 用户在 Grill-me 第 11 问采用推荐；红黄阈值可配置，默认 95%/50% |
| 选配采用同类型替代组 | 用户在 Grill-me 第 12 问采用推荐；一个默认项加多个备选，每个 BOM 位置只使用并输出当前项 |
| 技术与生产 BOM 使用不同展开口径 | 用户在 Grill-me 第 13 问采用推荐；技术按路径、生产按叶子汇总，均只计算当前选配项 |
| 批量导出为独立 Excel 后打包 ZIP | 用户在 Grill-me 第 14 问采用推荐；便于独立归档并避免 Sheet 命名限制 |
| 首期不做审批流 | 用户在 Grill-me 第 15 问采用推荐；变更立即生效但必须填写原因并记录完整前后值 |
| 局域网 Windows 单机部署 | 用户在 Grill-me 第 16 问确认符合环境；SQLite 使用本地磁盘，浏览器访问并每日备份 |
| 首批按单人操作设计 | 用户在 Grill-me 第 17 问明确只有 1 人操作；不引入高并发相关复杂度 |
| 模块对比采用差异矩阵表 | 用户在 Grill-me 第 18 问采用推荐；1–5 个同类型对象按叶子原材料和累计数量比较 |
| xlsm 用作一次性初始化迁移输入 | 用户进一步澄清第 19 项边界；用于形成首版数据库，但不是日常输入、项目产出或运行依赖 |
| 初始化迁移采用预检确认和对账 | 用户最终确认第 19 项；异常人工处置后入正式库，原始 xlsm 不修改 |
| 首版编码规则按指定资料初始化 | 用户在 Grill-me 第 20 问采用推荐；初始化后数据库规则是唯一运行来源 |
| 编码规则覆盖采用受控事务替换 | 用户在 Grill-me 第 21 问采用推荐；先预览兼容性与差异，保留旧快照，失败回滚 |
| 停用对象禁止新增引用但保留历史引用 | 用户在 Grill-me 第 22 问采用推荐；已有 BOM 继续计算并显示状态警告 |
| 产品机型归属由 BOM 自动计算 | 用户在 Grill-me 第 23 问采用推荐；有效/试产为当前归属，停用为灰色历史归属，不允许手改 |
| 删除采用引用保护和软删除 | 用户在 Grill-me 第 24 问采用推荐；有引用禁止删除，编码永久占用且无引用对象可恢复 |
| 复制分为新版本和新物料 | 用户在 Grill-me 第 25 问采用推荐；均复制组成并记录来源，但不复制历史日志 |
| 新建半成品/单元/整机默认试产 | 用户在 Grill-me 第 26 问采用推荐；原材料不使用有效/试产/停用三态 |
| 外协/自制改外购前先清空组成 | 用户在 Grill-me 第 27 问采用推荐；不自动删关系，需预览影响、填写原因并人工清空 |
| Excel 导入按所选行原子提交 | 用户在 Grill-me 第 28 问采用推荐；暂存可分批处理，每次所选行失败整组回滚 |
| BOM 正式输出按人工显示顺序 | 用户在 Grill-me 第 29 问采用推荐；生产 BOM 汇总后保留叶子料首次出现位置 |
| 日常 Excel 导入首期仅支持原材料 | 用户在 Grill-me 第 30 问采用推荐；其他对象使用页面录入和复制，历史初始化使用专用迁移脚本 |

## Errors Encountered

| Error | Attempt | Resolution |
|-------|---------|------------|
| 当前目录执行 `git status` 返回“not a git repository” | 1 | 记录为无 Git 仓库，不再依赖 Git 状态 |
| Office/PDF 批量提取输出超出显示上限并被截断 | 1 | 改为按主题、按文件提取精简摘要 |
| 工作簿数据规模统计超时 | 1 | 原因为只读模式随机访问反复扫描；改用单次顺序遍历 |
| 第 1 次同步 Grill-me 决策时补丁上下文不匹配 | 1 | 用 `rg` 定位准确文本后重新应用；首次未产生部分修改 |
| PowerShell 混合输出导致中文表头显示为乱码 | 1 | 表头语义由此前 Unicode 提取结果交叉确认；数值和结构统计不受影响 |
| 第 1 次写回生产 BOM 核验结果时大补丁上下文不匹配 | 1 | 拆成逐文件小补丁更新，避免跨文件上下文耦合 |
| 第 1 次同步第 11 项决策时跨文件补丁上下文不匹配 | 1 | 改为逐文件小补丁；后续规划更新不再使用跨文件大补丁 |
| 第 1 次同步第 18 项到 findings 时相邻上下文已变化 | 1 | 改为按单行精确更新并成功写入 |
| 最终一致性检查的 `rg '*.md'` 在 PowerShell 中路径语法错误 | 1 | 改用 `rg -g '*.md'` 的 glob 参数形式 |
| 最终校验未识别第 34 项决策 | 1 | 正则缺少多行模式；改用 `(?m)^34\.` 后重新校验 |
| 历史 xlsm 首次移动失败，文件被占用 | 1 | 定位为本任务超时遗留的 Python 只读进程，核验后结束进程并成功移动 |
