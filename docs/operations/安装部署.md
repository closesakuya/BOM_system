# BOM V1.2 安装部署

当前版本的变化、演示和升级说明见 [V1.2 使用与部署](V1.2使用与部署.md)。保留原安装入口；V1.2 先备份再升级，未升级数据库会被启动检查阻止。

## 环境要求

- Windows 10/11 或 Windows Server，Python 3.12 或 3.13、Node.js 18、npm。
- SQLite 数据库必须放在运行主机本地磁盘，不放网络共享目录。
- 首批单实例运行；局域网用户通过浏览器访问主机的 8000 端口。

## 首次安装

在项目根目录用 PowerShell 执行：

```powershell
.\scripts\install_v1.ps1
```

脚本会检查项目虚拟环境是否真实可运行。若 `.venv` 不存在或从其他电脑复制后仍引用旧 Python 路径，脚本会查找系统默认 Python 并重建环境。随后安装依赖、构建前端。数据库不存在时，使用新版 `BOM物料清单管理.xlsm` 构建独立候选库并验证后启用，创建四种角色账户；存在数据库时不重复导入、不重置账户，只执行必要的旧版本升级和完整性检查。详见[四次需求部署说明](四次需求使用与部署.md)。

生产使用前应设置随机密钥和初始密码：

```powershell
$env:BOM_SECRET_KEY = "替换为长随机字符串"
.\scripts\start_v1.ps1
```

新版生产账户为 admin、dev、product、guest，密码从本地配置读取或安装时输入；后续通过管理员账户管理页面重置。`admin123` 仅用于隔离自动化测试，不能当作生产初始密码。已有库的账户不会被安装脚本覆盖。

## 启动和访问

```powershell
.\scripts\start_v1.ps1 -Port 8000
```

启动脚本优先使用项目 `.venv`。如果 `.venv` 不存在、已损坏，或从另一台电脑复制后仍指向旧 Python 路径，脚本会自动尝试 PATH 中的系统默认 `python`，不依赖固定安装目录。系统 Python 必须已经安装 `backend/requirements.txt` 中的依赖。

本机访问 `http://127.0.0.1:8000`；局域网访问 `http://主机IP:8000`。防火墙需允许所选 TCP 端口。

`0.0.0.0` 仅表示服务监听本机所有网卡，不是浏览器可访问的网址。启动脚本会自动列出本机和检测到的局域网访问地址。

若需开机自启，可在 Windows 任务计划程序中创建“计算机启动时”任务，程序使用 `powershell.exe`，参数为：

```text
-NoProfile -ExecutionPolicy Bypass -File D:\实际目录\scripts\start_v1.ps1
```

工作目录设为项目根目录，失败后每 1 分钟重试三次。

## 覆盖升级到 V1.1.1

交付目录直接覆盖旧程序文件后，在项目根目录重新执行：

```powershell
.\scripts\install_v1.ps1
```

不需要先手工迁移数据库。升级备份写入 `runtime/backups`，JSON/XLSX 对账报告写入 `runtime/reports`。升级失败时事务不会提交；请保留错误信息和报告，不要反复手工修改数据库。

## 数据库结构工具

项目保留 Alembic 基线供开发环境创建空库；现有正式库的 V1.1/V1.1.1 升级以安装脚本调用的幂等升级器为准：

```powershell
.\.venv\Scripts\alembic.exe -c backend\alembic.ini upgrade head
```

不要用应用启动代替正式升级；部署更新后先运行 `install_v1.ps1`，确认迁移和验证成功，再运行 `start_v1.ps1`。
