# 四次需求：使用与部署

当前有效业务口径见 [确认稿](../requirements/四次需求-确认稿.md)。保持 V1.2 程序版本标识，本次新增生产数据重建和四角色权限。

## 页面与 Excel

- 网页查看、详细信息、BOM 编辑仍按行显示选配，实际数量只计算选用项。
- 单个和批量 Excel 导出：动态“选配组”合并表头，当前选用在第一列，其余备选依次排列；备选不再单独展开行。
- 选配列显示 `物料编码(名称 占比%)`。名称超过 6 字符只在这一列缩写为前 3 字符 + `..` + 后 3 字符。
- 生产 BOM 主表按物料、选配内容及占比一致才汇总；上层选配放“上层选配说明”，不计入原材料用量。
- 关闭“显示选配替代”时 Excel 不显示选配列或上层说明；没有选配的表也不显示空选配列。

## 四种账号

| 账号 | 权限 |
| --- | --- |
| admin | 全部权限，编辑用户名及重置密码 |
| dev | 除账户管理外的全部业务维护、规则、导出及备份 |
| product | 查看、导出；新建、修改、删除未封存的未正式原材料档案，不能编辑组成、选配或转正式 |
| guest | 只读，不导出、不修改 |

初始化密码从本地账户配置读取或交互输入，不存入源码。使用用户提供的初始密码登录；后续管理员在“账户管理 → 编辑 / 重置密码”调整。留空新密码表示不修改，无法查看现有密码。

## 首次安装

准备 `data/migration/BOM物料清单管理.xlsm`、`data/templates/新增原材料编码登记表(模版).xlsx`，执行 `scripts/install_v1.ps1`。无数据库时脚本构建独立候选库、验证后启用；若存在本地 `docs/requirements/四次需求.md`，读取其中账号配置，否则交互输入四个初始密码。已有数据库时只检查升级，不重新迁移业务数据、不重置密码。

日常启动仍使用 `scripts/start_v1.ps1`，本机访问 `http://127.0.0.1:8000`。不要将 `0.0.0.0` 当作浏览器地址。建议设置环境变量 `BOM_SECRET_KEY` 为部署专用随机值；改动后已有登录令牌失效，需重新登录。

## 明确重建已有数据库

**仅在需要用新版初始数据替换当前数据时使用；正常升级不要执行重建。**

1. 停止 BOM 服务，避免业务写入。
2. 执行 `scripts/rebuild_production.ps1` 只构建和验证候选库，不修改当前库。
3. 检查候选库旁的 `.report.json`。正式执行重建可使用 `scripts/rebuild_production.ps1 -Activate`，输入 `REBUILD` 后重新构建、备份并启用。
4. 如需启用已经核验的候选库，在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m backend.app.production_rebuild --activate runtime/实际候选库文件.db
```

旧库在线一致性备份保留在 `runtime/backups/before-production-rebuild-*.db`，激活记录在 `runtime/reports/production-activation-*.json`。原 Excel 不修改，旧测试档案和旧账户不带入新库；演示物料重新生成，不覆盖正式编码。

本次转换：排除 J00.001.01 及 16 条组成、错误物料 Y13.3005.0 及 4 条引用（对应父项保留）；移除 44 个 X 临时半成品并将父项改接第一个原材料、建立平均占比选配；44 条零数量组成按 1 导入；36 个 99 编码保留，后续从现存最大编码后递增。8 个带空格的关键器件码沿用去空白规则，原辅助索引码保留；以上转换都有报告或审计记录。

错误物料已在本地正式库定向删除，并加入重建排除规则。仅拉取代码不会删除其他服务器既有数据库中的同名物料；不要为此直接重建整个数据库。运行数据和备份不随 Git 发布。

可用 `-AccountsFile runtime/accounts.json` 指定本地 JSON 账户文件，键为 admin、dev、product、guest，值为对应密码；不要将文件提交 Git。缺少依赖先执行安装脚本，跨机器不依赖固定 Python 安装路径。

## 测试隔离

后端测试使用临时库；浏览器测试从源库备份到 `runtime/e2e.db`，仅在副本设置测试密码。可用环境变量 `BOM_E2E_SOURCE` 指定候选源库。不得把 e2e.db 用作生产库。
