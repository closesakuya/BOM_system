# BOM 轻量级 Web 系统项目方案（确认版 v1.0）

> 状态：已通过 Grill-me 逐项确认，可作为实施与验收基线。

## 1. 建设目标

参考现有 Excel 的字段、层级和输出样式，建设一个可在局域网部署的轻量级 Web 系统，统一管理原材料、半成品、单元和整机，可靠处理编码、BOM 组成、选配、展开/汇总、追溯、比较与变更审计，并可按系统模板导入和导出 Excel。[BOM物料清单管理(1).xlsm](<../../data/migration/BOM物料清单管理(1).xlsm>) 作为一次性的历史数据初始化输入，用于形成首版数据库；它不是系统日常输入模板、项目产出或运行依赖。

首要成功标准：新系统对已选取的代表性整机生成的技术 BOM 与生产 BOM，在既定口径下与人工确认结果一致；新增和维护操作不会产生重码、非法引用或 BOM 环路。

## 2. 技术方案

| 层次 | 推荐 | 说明 |
|------|------|------|
| 前端 | Vue 3 + TypeScript + Vite + Element Plus | 已确认；承载导入预览、树、拖拽、批量勾选和对比矩阵 |
| 后端 | Python 3.12 + FastAPI + Pydantic | 已确认；承载领域规则、递归计算、Excel 和审计 |
| 数据访问 | SQLAlchemy 2 + Alembic | 隔离数据库细节，支持可追踪的结构迁移 |
| 数据库 | SQLite（WAL、外键开启、定时备份） | 满足首批单人使用的轻量场景 |
| Excel | openpyxl | 处理系统定义的 xlsx 导入模板和模板化导出，并一次性读取历史 xlsm 数据；绝不执行其中 VBA |
| 相似检查 | Unicode NFKC 文本规范化 + RapidFuzz | 四类物料统一使用已确认的 95%/50% 可配置阈值 |
| 测试 | pytest + API 集成测试 + Playwright 关键流程测试 | 同时覆盖图算法、导入事务和浏览器交互 |
| 部署 | 局域网单台 Windows 主机，Python 应用注册为后台服务 | SQLite 放主机本地磁盘，其他电脑通过浏览器访问，不依赖互联网 |

首批只有 1 名实际操作人员，不为并发引入 Redis、消息队列、独立搜索引擎或分布式组件。批量任务采用简单的数据库任务记录并顺序执行。数据库和上传文件按日自动备份，并提供人工立即备份与恢复演练流程。

## 3. 核心架构

### 3.1 统一物料模型

四类对象共用 `item` 主表，以 `item_type` 区分原材料、半成品、单元、整机，四个业务页面分别呈现各自字段和操作。这样可统一实现编码唯一性、名称补全、状态、复制、反向引用、相似检查和审计。

外购、外协、自制已确认为原材料的“来源属性”，不增加新的物料类型。界面提供外购库、外协库、自制库三个筛选入口。“是否需要组装”由实际 BOM 组成关系派生：外购或外协原材料没有组成时按普通叶子原材料维护，允许修改名称、规格型号、备注等档案；新增第一条组成后自动成为组装原材料，移除最后一条组成后自动恢复为叶子。自制原材料新建时仍必须至少维护一条原材料组成关系。已有组成的外协/自制原材料不能直接改为外购：用户必须先查看受影响 BOM、填写变更原因并删除全部组装来源，系统不会自动删除关系；清空后才能修改来源属性。

### 3.2 BOM 关系图

使用 `bom_line(parent_item_id, child_item_id, quantity, sort_order, line_remark)` 表示组成。数量采用定点小数；单位继承子物料档案，不在 BOM 行重复保存。同一父项下同一子物料只保留一行，重复添加时合并数量。首期不加入损耗率、工位、位号和生效日期。页面仍体现原材料→半成品→单元→整机的业务层级。已确认半成品不能包含半成品；唯一允许的同类型递归关系是“原材料包含原材料”，用于将多个原材料组装成新的原材料。

允许的父子关系采用白名单：

| 父项 | 允许的子项 |
|------|------------|
| 原材料 | 原材料 |
| 半成品 | 原材料 |
| 单元 | 半成品、原材料 |
| 整机 | 单元、半成品、原材料 |

该规则保留现有工作簿中的跨层直挂，其他父子类型组合一律拒绝。

每次新增、替换、导入或复制关系，都在同一事务内执行：

1. 类型组合校验；
2. 父子不能相同；
3. 递归可达性检查，阻止形成环；
4. 数量和单位校验；
5. 明确拒绝半成品→半成品、单元→单元、整机→整机关系；
6. 写入关系及审计事件；
7. 使 BOM 展开缓存和产品归属缓存失效（若启用缓存）。

### 3.3 编码与版本

用可维护的编码规则表保存分类、固定片段、可选片段、流水号位置/范围、版本位和示例。首版原材料规则以 [新增原材料编码登记表(模版).xlsx](<../../data/templates/新增原材料编码登记表(模版).xlsx>) 的“表2 原材料分类及编码规则表”为准；半成品、单元、整机规则参考 [物料编码标准.doc](../reference/物料编码标准.doc) 和历史 xlsm 中的已有编码。初始化后，数据库规则成为唯一运行来源，不再运行时读取这些文件。新增时按规则逐级选择并在事务中分配第一个可用编号；页面显示当前最大编码及其物料，但后端在保存时再次抢占校验，避免并发重码。

编码规则 Excel 覆盖采用受控替换：上传后先校验并展示新增/修改/删除差异，同时检查现有编码的兼容性；用户确认后在单一事务中整体替换。替换前保存规则快照和审计日志，任何错误都整批回滚。

编码已确认拆成“编码主体 + 版本尾号”。完整编码全局唯一；同一主体允许存在多个版本，并通过显式版本系列关系关联，而不是仅靠字符串推断。新物料生成新主体流水号；复制为新版本时只递增版本尾号。历史 `.0/.1` 等完整编码原样保留，内部解析为数值版本；后续新版本按两位尾号生成，例如现有最大版本为 `.1` 时推荐 `.02`。

现有文件的字段语义统一为：`10.1001.0` 这类“物料识别码”是系统核心完整编码、全局唯一约束和 BOM 引用键，界面命名为“系统物料编码”；`B01.A` 这类旧“物料编码”保存为可选的“辅助索引码”，用于搜索和历史兼容，不参与新编码生成且不强制填写。

复制提供两种明确模式：“复制为新版本”保持编码主体、递增版本尾号；“复制为新物料”按规则生成新主体且版本从 `.01` 开始。两者都复制当前组成关系并进入编辑页确认后保存；不复制历史日志，只在新对象审计中记录来源对象。

新版本创建后，所有既有 BOM 继续引用原版本，不自动升级。新建 BOM 选料时默认推荐同主体下最新的未删除、未停用版本；升级既有 BOM 必须通过反向追溯和批量替换显式执行，预览影响、填写原因并记录审计。旧版本永久保留用于历史追溯。

### 3.4 重复与相似检查

保存前先规范化全角/半角、大小写、空白、常用标点和单位表达，再执行：

- 编码精确唯一检查；
- 名称+规格的精确/高相似检查；
- 名称近似候选提示。

名称+规格高度相似不会绝对禁止创建：只要完整物料编码不重复，用户查看已有相似物料并进行二次确认后仍可创建。完整编码冲突始终拒绝。四类物料统一采用可配置分级：规范化后的名称+规格综合相似度 ≥95% 为红色并强制二次确认；名称相似度 50%–95% 为黄色并展示候选；名称相似度 <50% 不提示。用户日后上传的批量导入文件不直接进入正式表，而进入 `import_batch` / `import_row` 暂存区，逐行展示红/黄/无色状态、命中对象、原因和建议动作。用户可以分批勾选提交；每次所选行在一个事务中原子写入，任一行失败则本次所选行全部回滚，未选和待修正行继续保留在暂存区。

### 3.5 选配模型

采用 `alternative_group` + `alternative_member`：成员必须为同一物料类型，每组有一个默认/优选项和多个备选项。一个 BOM 位置同一时间只选择其中一个，编辑时可在该组内替换；BOM 行同时记录选配组和当前选中物料。已建替代组允许修改组名、类型、默认项、成员和启用状态，所有更新写入审计；仍被 BOM 当前选中的成员不能移出组，被 BOM 引用的组不能停用，修改默认项不会自动改写已有 BOM 的当前选中项。未绑定的 BOM 行若当前物料属于有效替代组，界面自动展示第一个可用组和候选供查看，已有绑定组优先；自动展示不写库。页面选择候选只形成待保存状态，用户明确确认后才在同一事务中绑定组并切换当前物料；保存成功不改变行数量、顺序和备注。同一父项的其他直接 BOM 行已使用目标物料时，后端拒绝保存且前端弹窗提示，不合并数量；目标物料仅出现在半成品或单元等下级路径时不构成冲突，父项仍可直接选配。预览、比较和导出默认只计算当前选中项，不把全部备选同时计入数量。原材料、半成品、单元可以建立选配组，整机本身不建立选配组。

### 3.6 BOM 输出与比较

- 技术 BOM：按树形路径深度优先完整展开，不合并重复物料；同一物料出现在不同分支时分别显示，数量表示相对直接父项的本层用量。
- 生产 BOM：递归展开到叶子原材料，沿完整路径逐层相乘，并按完整物料编码汇总为一行。
- 正式排序：技术 BOM 在每个父项内按 BOM 行显示顺序排列后递归展开；生产 BOM 合并重复叶子料后保留其在技术 BOM 中首次出现的位置。BOM 编辑器支持拖拽调整显示顺序；页面临时按编码/名称排序不会改变正式导出顺序。
- 批量导出：每个所选对象生成一份独立 Excel，再统一打包为 ZIP 下载；文件名格式为“完整编码-名称-技术BOM/生产BOM.xlsx”，并处理 Windows 非法字符和重名。
- 模块比较：选择 1–5 个同类型对象，以叶子原材料为行、所选对象为列，单元格显示累计数量；缺少物料和数量不同使用不同颜色，点击差异可下钻到来源路径，并支持导出 Excel 对比表。首期不做复杂关系图。

经核验 [00.005.01-TN水质分析仪-D60-YJ-BZ-A1-I-16C-11-0-生产BOM.xlsx](../../data/samples/00.005.01-TN水质分析仪-D60-YJ-BZ-A1-I-16C-11-0-生产BOM.xlsx)，生产 BOM 导出基准如下：

- 第 1 行为所选对象的完整编码与名称，横跨全部列；
- 第 2 行为表头；
- 明细列依次为：序号、物料编码、名称、规格型号、单位、数量、备注（黄色：修改后名称）、上一版本名称、发票名称、材料属性、变更记录；
- 样表有 231 条明细，物料编码无重复，说明相同叶子料需要汇总为一行；
- 数量包含 `0.013` 等小数，数据库和计算过程使用 `Decimal`/定点数，禁止浮点累计；
- 规格型号、备注、上一版本名称、发票名称、材料属性和变更记录允许为空；
- 样表文字提示黄色代表修改后名称，但该文件实际没有带填充色的明细单元格；系统导出将依据明确的变更规则渲染，而不依赖源文件颜色猜测。

上述 11 个字段是“生产 BOM 输出字段”，其中只有子物料、数量、顺序、行备注属于 BOM 关系；名称、规格、单位、物料备注、上一版本名称、发票名称和材料属性来自物料主数据，变更记录来自审计/历史数据。

技术 BOM 参照现有宏工作簿输出 12 列：序号、层级、物料编码、名称、规格型号、单位、数量、备注、上一版本名称、发票名称、材料属性、变更记录。技术 BOM 与生产 BOM 都只计算当前选中的选配项。

### 3.7 反向追溯与归属产品

通过递归查询计算“该物料被哪些父项和整机使用”，并展示整机状态。“当前在用归属产品机型”完全以 BOM 事实自动计算，不允许人工编辑：有效、试产整机显示为当前归属，停用整机保留在历史归属中并灰显；BOM 结构或整机状态变化后自动更新。物料页面可从产品机型下钻到具体引用路径。如性能需要，可维护随时可重建的计算缓存。

半成品、单元和整机的状态为“有效 / 试产 / 停用”，新建默认“试产”，创建时允许改为“有效”，不能以“停用”为默认；所有状态变化写入审计。有效和试产对象可以正常加入 BOM；停用对象不能被新增引用或作为选配替换目标，普通搜索默认隐藏但可切换查看。已有引用不会因停用而自动删除，预览和导出仍按原结构计算并显示停用警告。原材料不设置这组三态，使用来源属性、引用保护和软删除管理。

删除采用受保护的软删除：对象被 BOM、选配组或版本关系引用时禁止删除，并展示全部引用位置；无引用时只标记为已删除，默认列表隐藏，管理员可从专门页面恢复。审计和历史记录继续显示原编码/名称，完整编码永久占用，不因删除而重新分配。

### 3.8 变更审计

采用追加式审计事件：操作人、时间、对象、动作、变更原因、批次号、前值、后值。新增/删除 BOM 行、替换、调量、编码修改、状态变化、选配变化、复制和批量导入都必须记录。首期不做审批流，维护人员确认后立即生效；批量操作必须先展示影响范围。日志对包括管理员在内的所有账户只读，不允许修改或删除；错误只能通过新的修正操作追加记录。日志支持筛选、对象时间线和 Excel 导出，不提供直接覆盖当前数据的“一键回滚”，需要恢复时通过新的受审计变更完成。

### 3.9 简化账户与权限

首期包含基础登录和固定角色，以便识别操作人并限制写操作：

- 管理员：账户、编码规则和全部业务数据；
- 维护人员：物料/BOM 的新增、编辑、导入、批量维护和导出；
- 查看人员：查询、预览、比较和导出。

权限管控不是建设重点，因此首期不做部门级数据隔离、字段级权限、自定义角色设计器或复杂授权继承。账户保留所属部门等基础信息，用于日志展示和未来扩展。

## 4. 功能模块

1. 工作台：待处理导入、近期变更、数据质量告警。
2. 物料中心：四类对象的列表、详情、新增、编辑、复制、状态与反向引用。
3. 编码规则：规则维护、Excel 覆盖导入、编码预览、最大值/下一号提示。
4. BOM 编辑器：搜索选料、数量维护、树形展开、引用树、环路阻止、选配替换。
5. Excel 导入中心：首期仅支持原材料档案的日常批量导入，提供上传、字段映射、规则校验、相似预览、逐行决策、提交及结果下载；半成品、单元、整机及其 BOM 关系通过页面录入和复制维护。历史 xlsm 初始化迁移使用一次性专用脚本，不作为日常导入功能。
6. BOM 预览/导出：技术 BOM、生产 BOM、单个及批量导出。
7. BOM 维护：首期包含按物料反查多个 BOM 后批量替换、调量、增加、删除；操作前展示影响范围和差异预览，提交时强制填写变更原因，并以一个批次号记录审计。
8. 选配中心：同层选配组、优选/备选、被使用位置。
9. 模块比较：1–5 个同层对象的结构/叶子物料差异矩阵。
10. 变更日志：历史时间线、条件检索、详情差异、Excel 导出。
11. 数据初始化与导入质量：一次性解析历史 xlsm，经预检确认后形成首版数据库；日常导入使用系统模板、暂存预览和结果报告。
12. 简化账户与权限：基础登录、三个固定角色和账户启停。
13. 通知：首期不做主动推送，仅提供近期变更、日志查询、对象时间线和日志 Excel 导出；站内/外部推送列为后续扩展。

## 5. 数据实体

- `item`、`item_attribute_value`、`dictionary_value`
- `bom_line`
- `code_rule`、`code_rule_segment`、`code_allocation`
- `alternative_group`、`alternative_member`
- `import_batch`、`import_row`、`import_decision`
- `audit_event`、`audit_change`
- `user`、固定 `role`（首期启用简化权限；部门作为用户基础信息或字典）
- `export_job`；`notification` 暂不纳入首期

数据库关键约束包括：完整编码唯一、父子关系唯一策略、正数量、有效外键、受控状态值。图无环和模糊相似属于跨行逻辑，由领域服务在事务中保证并用测试锁定。

## 6. 实施里程碑

### M0：口径确认与历史数据剖析

- 完成 Grill-me 决策清单。
- 确认字段字典、编码/版本、允许的层级组合、选配和两类 BOM 输出口径。
- 根据历史工作簿确定字段字典、迁移映射、数据质量清单和黄金 BOM 验收样本。
- 验收：所有阻塞开发的决策有负责人和结论。

### M1：工程底座与物料/编码

- 建立前后端、数据库迁移、配置、日志、备份恢复基础。

- 完成精确唯一校验和基本相似提示。
- 验收：并发保存不产生重码；关键字段和规则可维护。

### M2：BOM 图与预览导出

- 完成组成编辑、树、反向引用、无环校验。
- 完成技术 BOM、生产 BOM、数量累计和 Excel 导出。
- 验收：黄金样本结构和数量 100% 对账；环路场景全部拒绝。

### M3：导入、选配与复制

- 完成 Excel 暂存预览、红黄提示、逐行决策和事务提交。
- 完成选配组、编辑时替换、复制关系。
- 完成多对象批量导出。
- 验收：失败导入不污染正式数据；选配输出符合确认口径。

### M4：批量维护、比较、归属与审计

- 完成反向检索后的批量变更。
- 完成 1–5 模块差异矩阵和下钻。
- 完成产品归属、状态联动、变更时间线和日志导出。
- 验收：所有受控变更均有可追溯前后值和原因。

### M5：初始化迁移、UAT 与上线

- 将历史 xlsm 解析到迁移暂存区：无冲突数据可批量确认，重码、孤儿、字段错位和无法识别的引用形成异常清单；人工确认处置后再写入正式库。迁移完成后对实体数量、关系数量和代表性 BOM 进行对账，原文件保持不变并归档。
- 准备初始管理员和经确认的基础字典/编码规则。
- 完成简化权限、性能、安全、备份恢复和用户验收。
- 编写部署、操作、备份恢复和故障处理文档。
- 验收：迁移实体/关系数量对账、黄金 BOM 样例和代表性业务流程通过，备份可恢复。

## 7. 测试与验收重点

- 编码：规则边界、流水耗尽、版本递增、并发冲突、规则覆盖导入回滚。
- 去重：中文标点/空格/大小写规范化、阈值边界、历史重复豁免、批量逐行决策。
- 图算法：直接环、间接环、深层嵌套、跨级直挂、删除/替换后的环路。
- 数量：多路径复用、倍数相乘、同料汇总、小数精度和单位一致性。
- 选配：默认/指定配置、备选停用、替换后的 BOM 和审计。
- 导入导出：现有模板、非法列、重复行、部分确认、全批回滚、样式与字段顺序。
- 审计：批量操作逐项可追溯、前后值完整、日志导出一致。
- 恢复：SQLite 在线备份、恢复演练、数据库结构升级回退方案。

## 8. 主要风险与控制

| 风险 | 控制措施 |
|------|----------|
| 多份需求材料口径冲突 | 先完成决策清单，建立需求优先级和验收样本 |
| 历史工作簿存在重码、孤儿、字段错位或与最终口径不一致 | 先进入迁移暂存区，输出冲突报告并人工确认，不自动猜测修复；以本次 Grill-me 结论为目标口径 |
| SQLite 并发写入能力有限 | WAL、短事务、单实例写入、批量任务串行化，并定义升级阈值 |
| 模糊匹配误杀合法物料 | 分离“阻止”和“提醒”，阈值可配置并记录人工决策 |
| BOM 递归和数量计算错误 | 仅允许原材料同类嵌套；使用单一图服务、路径测试、黄金样本对账、深度/节点上限保护 |
| 选配配置选择错误导致输出偏差 | BOM 行只保存一个当前选中项，预览/比较/导出显示当前配置并测试替换审计 |
