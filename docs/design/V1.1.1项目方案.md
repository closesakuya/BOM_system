# BOM V1.1.1 项目方案

> 状态：已于 2026-08-31 完成实施与验收  
> 需求依据：`docs/requirements/V1.1.1未正式原材料调整-确认草案.md`

## 1. 交付目标

V1.1.1 统一重构未正式原材料的编号、转正式和追溯方式：彻底取消显示编码前加 `Y`，改用系统永久分配的 `99.XXXX.X`；将“平台编号规则”替换为“关键器件码”；转正式时创建正式新物料并永久封存来源，在不改变既有有效 BOM 的前提下形成可审计、可查询、可导出的双向来源关系。

## 2. 数据模型设计

### 2.1 原材料字段

- `platform_code_rule` 迁移并重命名为 `key_component_code`，只适用于原材料。
- 增加 `historical_item_code`，保存迁移前编号或 Excel 未正式行的来源编号。
- 增加未正式状态：`pending`（待转正式）与 `archived`（已转正式封存）；正式物料该状态为空。
- 增加独立的转正式关联表：来源物料唯一，目标物料在历史迁移场景允许被多个来源关联；同时记录操作人、时间和变更说明。

### 2.2 编码与约束

- 未正式物料只允许 `99.0001.0` 至 `99.9999.9`，全库永久唯一，删除和封存不回收。
- 通过数据库序列表和服务端写事务原子取号；页面只显示预计编号，提交结果以服务端最终编号为准。
- 正式编码规则、导入和建议服务统一排除 `99.*`；未正式新建不接收用户指定的系统编码。
- 关键器件码可空；非空统一去除空白、转大写并校验 `[A-Z0-9]{3}\.[A-Z0-9]`。允许重复，重复仅返回关联物料提示。

## 3. V1.1 数据迁移

1. 升级前创建带时间戳的数据库备份并校验备份完整性。
2. 在单个数据库事务中升级结构，迁移 208 条平台编号值为关键器件码；规范化 7 条含空白值并写审计。
3. 按内部 ID 顺序将现有 27 条未正式原材料编号为 `99.0001.0` 至 `99.0003.6`，原编码写入历史物料号。
4. 将这 27 条全部设为“已转正式（封存）”，依据 V1.1 已确认映射建立历史来源关系；原先已改接的 10 条有效 BOM 不再变动。
5. 初始化序列，使下一条新建未正式物料预计从 `99.0003.7` 开始。
6. 校验编号唯一、状态合法、来源关联、历史有效 BOM、替代组、环路及审计数量；失败时整次回滚并保留升级前数据库。
7. 输出 JSON 与中文 Excel 迁移报告；迁移可重复执行且不得重复编号、关联或审计。

## 4. 后端业务服务

### 4.1 新建与编辑

- 未正式原材料新建接口忽略客户端编号，事务内取得最终 `99.*`；正式物料继续使用大类、小类、规则、实时查重和建议编码。
- 正式与待转正式原材料可维护关键器件码；封存来源的档案、BOM、替代、删除、恢复和再次转正式写操作统一由后端拒绝。
- 搜索同时覆盖系统物料号、历史物料号、名称、规格和关键器件码；自动补全返回足够的状态和来源辨识字段。

### 4.2 转正式事务

1. 只接受状态为 `pending` 的未正式原材料，并要求变更说明。
2. 使用完整原材料新建数据，重新选择正式大类、小类和编码规则；禁止 `99.*`，执行格式、重复与相似度检查。
3. 预检来源全部直接组成和展开路径：删除/停用子项、层级、环路、重复直接组成和替代组均须合法；一次列出全部问题。
4. 创建全新的正式原材料，复制提交时确认的业务档案以及全部直接 BOM 行、数量、顺序、行备注和合法替代组。
5. 建立来源关系、把原记录设为永久封存，并在来源、目标及转正式关联上记录同一批次审计。
6. 上述操作使用同一事务；任一步失败全部回滚，来源保持待转正式。

### 4.3 查询与有效关系

- 封存来源仍可查看、搜索、快速预览和导出自身档案及历史 BOM。
- 当前反向引用、用量汇总、机型归属和删除阻止查询排除以封存来源为父项的历史 BOM。
- 正式物料显示全部来源 `99.*`；封存来源显示目标正式物料；两端均支持快速查看与新标签打开完整页面。

## 5. Excel 导入与导出

- 原材料导入模板增加“导入状态”；缺列、空白或“正式导入”为正式，只有“未正式导入”为未正式，其余值在预览时报错。
- 未正式行的 Excel 物料号仅存入历史物料号；预览显示预计 `99.*`，整批提交按 Excel 行号在一个事务内连续分配最终编号。
- 关键器件码按统一规则校验和规范化；重复只警告，不阻止导入。
- 原材料基本信息导出增加“历史物料号、关键器件码、封存状态、来源未正式物料号、转正式物料号”，不暴露内部 ID。
- 封存来源的单项/批量技术和生产 BOM 可导出，并标注“封存来源，仅供历史参考”。

## 6. 前端交互

- 删除所有 `Y` 拼接和旧“平台编号规则”文案、控件及接口字段，统一为真实 `99.*` 和“关键器件码”。
- 未正式新建表单显示不可编辑的预计编号及“提交时可能因并发顺延”说明；成功后明确显示最终编号。
- 原材料列表增加“待转正式 / 已转正式（封存） / 全部未正式”筛选；封存详情整体只读并清晰显示封存提示。
- 转正式弹窗复用完整新建原材料表单与编码规则引导，展示待复制 BOM 摘要、校验问题、相似项和强制变更说明。
- 来源与目标关系、搜索候选、快速查看、历史记录及 BOM 中的物料号沿用全项目统一弹窗与新标签跳转逻辑。

## 7. 实施阶段

### 阶段 0：基线与迁移夹具

- 备份正式数据库摘要，固化 27 条来源、208 条关键器件码和历史映射夹具。
- 增加成功、失败回滚、重复执行和并发取号测试数据库。

### 阶段 1：结构与幂等迁移

- 实现新字段、状态、序列表、关联表、索引和约束。
- 实现 V1.1.1 迁移、审计、报告及完整性验证，并在正式库副本演练。

### 阶段 2：领域服务与 API

- 实现取号、关键器件码、封存写保护、搜索筛选及编码号段隔离。
- 重写转正式为新建正式物料的原子事务，并统一有效 BOM 查询口径。

### 阶段 3：Excel 与前端

- 改造导入预览/整批提交、基本信息和 BOM 导出。
- 完成新建、编辑、转正式、筛选、追溯、快速查看及中文状态展示。

### 阶段 4：回归、升级与交付

- 扩充后端、前端和 Playwright 场景，覆盖正常、冲突、并发、回滚、封存和历史多来源。
- 通过全量 pytest、TypeScript、生产构建、浏览器验收及数据库完整性检查。
- 更新版本为 V1.1.1，修改既有 V1 安装/启动脚本和运维文档；在升级前备份后执行正式迁移并出具验收报告。

## 8. 验收门槛

- 代码、API、页面和 Excel 中不再出现旧 `Y` 显示逻辑或“平台编号规则”对外字段。
- 现有 27 条稳定迁移且原有效 BOM 数量与指向不变；下一未正式编号正确且并发无重复。
- 新转正式一定创建新 ID，来源只读封存，双向可追溯，BOM 完整复制；故障时无半成品事务状态。
- 正式编码不能进入 `99.*`，未正式不能离开 `99.*`；关键器件码格式与重复提示符合确认口径。
- Excel 正式默认、特殊未正式、错误标记、批量原子提交和新增导出列均通过回归。
- V1.1 现有功能无回归；安装、启动、备份、恢复和从 V1.1 覆盖升级均验证通过。
