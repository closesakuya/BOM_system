# BOM V1.1 项目方案

> 状态：已确认并完成实施  
> 依据：`docs/requirements/V1.1确认需求.md`

## 1. 交付目标

在不破坏现有正式物料与 BOM 数据的前提下，完成机型追溯、未正式原材料、可编辑导入、半成品嵌套、替代占比、可控 BOM 展开、批量导出和复制删除修复。V1.1 采用覆盖升级，但数据库升级前必须自动备份，迁移失败不得污染现库。

## 2. 关键设计

### 2.1 数据模型与唯一性

- `items` 增加机型、正式导入状态、平台编号规则等必要字段；机型只对整机有效，平台编号只对原材料有效。
- 删除 `items.change_note`；现有内容先转换为审计记录。
- 放宽现有编码和版本系列的无条件唯一约束，改为“正式物料全局唯一、未正式原材料可重复”的条件唯一策略。
- 所有详情、跳转、BOM 关联和替代成员使用物料内部 ID；编码仅作业务显示和搜索条件。
- 组合半成品由直接 BOM 实时派生或由服务层可靠同步，禁止前端直接写入。
- 替代成员增加两位小数市场占比，服务端统一重分和尾差吸收。

### 2.2 领域约束集中化

- 建立统一的“物料能否作为子项”校验：物料类型层级、正式状态、停用状态、同父项直接重复和环路检查全部在后端兜底。
- 新增、替换、导入、复制和转正式均复用相同编码校验及建议算法。
- BOM 展开使用统一遍历器，通过参数控制技术/生产视图、选配候选、自制/外协原材料展开和备用路径计量，避免预览与 Excel 产生两套口径。
- 反向追溯和机型归属只统计未删除、有效的上游路径。

### 2.3 历史迁移

1. 创建带时间戳的数据库备份并完成完整性检查。
2. 在事务或数据库副本中应用结构迁移。
3. 将现有 `change_note` 转为历史记录。
4. 改接 10 条历史 Y/J 原材料 BOM 引用，并记录审计。
5. 规范化 27 条 Y/J 原材料的编码与正式状态；不处理非原材料 J 前缀记录。
6. 导入平台编号规则历史值，空值不填充。
7. 校验正式编码唯一、无非法未正式子项、无环路、引用计数一致后再提交/切换。
8. 输出机器可读和中文可读迁移报告。

### 2.4 前端交互

- 四类列表共用服务端搜索、筛选、分页选择和基本信息导出逻辑。
- 重码未正式原材料候选显示足够的辨识字段；所有导航参数使用物料 ID，并保持选中、高亮和新标签打开能力。
- Excel 导入预览采用逐行编辑弹窗，字段与原材料新建保持同源配置，避免两套表单逐渐不一致。
- 技术/生产 BOM 的两个展示开关相互独立，预览和导出共享状态；只保存在当前浏览器会话。
- 替代占比由后端返回最终分配结果，前端即时展示总和与自动调整结果。

## 3. 实施阶段

### 阶段 0：基线保护与详细设计

- 固化当前数据库摘要、代表 BOM 和现有自动化测试结果。
- 增加 V1.1 数据备份、迁移演练和回滚夹具。
- 列出所有仍按编码定位物料的 API/前端链接，统一改造范围。

### 阶段 1：数据库结构与幂等迁移

- 完成字段、条件唯一约束、替代占比和审计结构迁移。
- 完成 change_note、平台编号、Y/J 原材料及 10 条 BOM 引用迁移。
- 生成迁移报告，使用正式数据库副本完成重复执行和失败回滚验证。

### 阶段 2：物料领域服务与列表能力

- 实现机型、正式状态、平台编号、转正式和编码建议。
- 修复复制物料删除/恢复规则。
- 改造 ID 导航、重码搜索和四类列表的回车筛选、跨页选择及基本信息 Excel 导出。

### 阶段 3：原材料导入与批量导出

- 复用新建表单实现逐行导入预览编辑和整批原子提交。
- 支持自制/外协叶子先导入后补组成。
- 完成来源筛选后的原材料批量技术/生产 BOM ZIP 导出。

### 阶段 4：半成品嵌套、替换与引用追溯

- 放开半成品包含半成品，完成组合标签、筛选和环路路径校验。
- 完成 BOM 行替换并保持数量、顺序、备注及合规的替代组绑定。
- 完成机型引用汇总、在用/历史区分和下级变更审计回归。

### 阶段 5：选配市场占比与统一 BOM 展开器

- 扩展原材料/半成品/单元替代组及占比自动调整。
- 实现显示备用选配、备用路径标识和不计量规则。
- 实现自制/外协原材料展开开关、半成品嵌套完整展开和 50 层安全保护。

### 阶段 6：Excel 与界面收口

- 统一预览、单项导出和批量导出的列、树形层级、固定行高、文件名和开关说明。
- 完成全部中文提示、操作说明、筛选状态、空态和错误路径。
- 更新安装、升级、操作和迁移对账文档，版本统一为 V1.1。

### 阶段 7：全量验证与覆盖交付

- 后端单元/API/迁移测试，前端生产构建和 Playwright 全功能回归。
- 使用正式数据库副本验证数据数量、正式编码唯一性、Y/J 改接、BOM 环路、代表技术/生产 BOM 和 Excel。
- 演练全新安装、现库覆盖升级、迁移失败回滚和备份恢复。
- 通过验收门禁后再覆盖交付包，不修改用户正式库做测试。

## 4. 验收门禁

- 原有历史正式物料档案不被无意修改，代表 BOM 数量与路径保持一致。
- 27 条 Y/J 原材料和 10 条引用迁移与报告完全对账。
- 未正式原材料可重码、不占号、不可被上级引用；转正式冲突检查可靠。
- 四类搜索、筛选、跨分页选择和两种基本信息导出符合确认口径。
- 半成品嵌套无环路，组合标签自动变化；复制的新物料在无上级引用时可删除。
- 替换保持数量/顺序/备注；同层直接重复被阻止，间接同物料允许。
- 选配占比恒为 100%，备用分支不进入当前生产计量。
- 页面预览与 Excel 在两个开关下结果一致；Excel 文件名、层级和固定行高符合要求。
- 数据库迁移可重复执行；任何失败都能证明原库未被污染且备份可恢复。
- 后端测试、前端构建、Playwright 全回归和数据库完整性验证全部通过。

## 5. 风险控制

- **重复编码歧义：** 以内部 ID 为唯一导航键，候选展示辨识字段。
- **迁移误改非原材料 J 编码：** 迁移限定 `item_type=material`，并使用明确白名单和迁移对账。
- **BOM 展开口径分裂：** 页面与 Excel 调用同一展开服务及参数模型。
- **半成品递归：** 写入时阻止环路，读取时设置 50 层安全上限。
- **选配数量误计：** 备用路径使用显式标记，生产汇总只接纳当前路径。
- **覆盖升级风险：** 先备份、在副本演练、迁移原子提交，验证通过后才替换现库。
