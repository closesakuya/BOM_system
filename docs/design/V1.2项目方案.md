# V1.2 实施方案

需求基准：[三次需求确认稿](../requirements/三次需求-确认稿.md)。用户已授权实施，不再保留旧独立替代组的业务兼容。

## 路径选配

以“所属物料 ID + BOM 行 ID 路径”保存配置，而不是修改共用子组件档案。模式为继承（没有本地记录）、自定义、禁用；从最上级所属物料向下查找，首个覆盖生效。BOM 行 ID 不复用，复制时映射第一段，保留下级稳定路径。

统一 `EffectiveBOM` 计算树、生产汇总、反向追溯、机型归属及比较。备用项只展示，不混入实际数量；占比不参与数量计算。保存时校验实际与备用环路、类型、正式/停用状态和同父项重复。失效路径先返回完整影响清单，确认后事务清除并记录快照。

## 生命周期及迁移

彻底删除先检查全部外部 BOM 与路径候选引用，连同自身组成和自身配置删除，但不删除下级档案。转正式来源使用独立删除快照留存原正式编码/名称，禁止按复用编码重新连接。物料与 BOM 行使用单调 ID，历史仍独立保留。

V1.2 迁移先检查原库、使用 SQLite 在线备份并检查备份，再在 `BEGIN IMMEDIATE` 事务内建表、清除旧组、初始化状态/ID 高水位和处理旧软删除。失败回滚；重复执行由不可变审计标记识别。旧数据被保留父项引用则转停用，否则按无外部引用集合清理。

## 导入与导出

四类型混合导入以原始输入前缀作为分配约束。预览不占号，批内避重；提交先取得 SQLite 写锁再重算。完整指定编码冲突整批不创建，自动补码只在原范围顺延。99 前缀优先临时识别，正式导入仍遵循原编码规则。

原材料基本信息严格 13 列，顺序同列表；历史含本项档案、直接组成及人工说明。机型归属基于有效选用路径。组成筛选按实际直接 BOM，原材料来源不决定展开。

## 发布与验证

保留 `install_v1.ps1`、`start_v1.ps1` 入口。已升级数据库跳过旧迁移，避免旧校验否定新的删除快照；V1.2 示例采用一次性审计标记，不覆盖后续人工编辑。

后端覆盖继承、覆盖、禁用、拷贝、引用阻断、回滚、转正式删除追溯、补码竞争与混合导入；浏览器覆盖新交互及原有主流程。测试数据库与备份目录隔离，正式升级最后执行。
